Solum interactive demo

Four local scenarios against a real solum-sidecar binary on dev-local (ephemeral keys, client-asserted capability[]). This is a developer walkthrough — not a customer evaluation and not org-IAM RBAC. Pilot profiles refuse this posture. Track B / H3 CDR uses a separate stack (make up-h3).

Local developer demo with ephemeral test keys — not a production environment and not a customer evaluation (Solum dev-local.toml forbids that use). Encrypt deny/allow is fail-closed on the capability[] array the client sends, not physician vs intern RBAC. Audit export is a HELIOS-oriented envelope only — not live HELIOS signing. Dashboard binds 127.0.0.1; the sidecar token is injected by nginx, not this page.

Scenario 1 — Fail-closed empty capability[]

Encrypt requires an active consent grant for (patient/demo-ui, care_provision) covering patient_summary plus solum:crypto:encrypt in the JSON body (dev-local only; client-asserted). Empty capability[] → HTTP 403; the refusal appears in the live audit log as access.denied. Sending encrypt in the body as any actor string succeeds — there is no intern role.
