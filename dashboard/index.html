Solum interactive demo

Four local scenarios against a real solum-sidecar binary, built from the pinned Solum commit in PINNED_VERSIONS.txt (or make up-sibling from ../Solum). Fail-closed authorization, consent-gated crypto (Deny B), tamper-evident audit, and a HELIOS-oriented export envelope — on your machine. Track B / H3 CDR uses a separate stack (make up-h3).

Local demo with ephemeral test keys only — not a production environment. Real deployments use CustomerHeld / AWS-KMS custody; see Solum’s SECURITY-OVERVIEW.md. Audit export is a HELIOS-oriented envelope only — not live HELIOS signing.

Scenario 1 — Fail-closed authorization

Encrypt requires an active consent grant for (patient/demo-ui, care_provision) covering patient_summary (auto-granted when you click Encrypt as Dr. Amina). Only the physician holds solum:crypto:encrypt. The intern is denied with HTTP 403; the refusal appears in the live audit log as authorization.denied.
